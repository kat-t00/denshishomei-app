# 電子署名アプリ

介護事業所向けの、無料で使える対面電子署名アプリです。お手持ちの契約書・重要事項説明書PDFに記入欄を設定し、タブレットを渡して署名してもらえます。

**[アプリを開く](https://kat-t00.github.io/denshishomei-app/)**

会員登録・インストールは不要。PDFの読み込み、署名、完成書面の作成はブラウザ内で行います。遠隔署名サービスではなく、同じ端末を使った対面契約に対応しています。

## できること

- 複数ページPDFに署名・氏名・住所・続柄・日付・同意チェックを配置し、書式を保存・再利用
- 文字サイズをスライダーで調整。住所の改行・建物名、2〜4行分の枠の高さに対応
- 署名欄で実際に試し書きし、保存前に見本PDFで印字を確認
- 本人の自署、本人の意思に基づく家族の代筆、代理人による署名を区別して記録
- 本人だけで完結する書式、追加署名が必要な場合だけ使う書式、全員が署名する書式を設定
- 同じ家族が続けて記入する場合、氏名・住所・関係や立場を引き継いで確認・変更
- Apple Pencil・指・マウスによる手書き署名。「1画戻す」「全消去」「大きく書く」に対応
- 事業所名・担当者を事前登録し、現地では候補から選択
- 完成PDFを確認して確定し、署名済みPDF・監査記録・交付記録を保存・共有
- 暗号化した途中保存ファイルから契約を再開
- 保存したPDFと監査記録のハッシュ照合、交付記録の内容確認
- 署名済み書式の版管理、訂正・再署名の記録
- ライト／ダーク表示、画面内の詳しい使い方ガイド

新しい契約に録音機能はありません。旧版の音声付き記録の照合・再保存には対応します。

## はじめて使うとき

1. **準備**：公開URLを開き、「事業所・担当者を登録」で候補を登録します。
2. **書式を作成**：「新しいテンプレートを作る」から未記入PDFを選び、記入欄を配置します。関連項目は選択した署名欄に割り当てられます。見本PDFを確認し、署名方法と書式名を設定して保存します。
3. **署名**：ホームで書式を選び、事業者用の確認を行います。本人・代筆・代理署名に合った方法で記入します。
4. **確認**：担当者、交付方法、記入済みの完成PDFを確認して確定します。
5. **保存・交付**：署名済みPDFと監査記録を保存先で確認し、選んだ方法で控えを交付します。交付結果は別の交付記録として保存できます。対応端末では「共有」から端末の共有先へ渡せます。共有できないファイルは保存ボタンを使います。保存・共有ボタンを押しただけでは保存完了や相手の受領を判定できません。

詳しい項目の違い・操作手順は、ヘッダーの「使い方」で確認できます。署名自体が氏名欄を兼ねる書式では、別の活字氏名欄を配置する必要はありません。

本人が書けず家族に代筆を頼む場合は、本人の意思による代筆を選び、本人欄には本人名を記入します。家族自身の署名も必要な書式では、追加の署名欄を設け、代筆時の追加署名を必須にできます。代理署名では、記入する方の立場と代理権の根拠を別途記録します。

## 保存・バックアップ

| 保存するもの | 保存方法・再開方法 |
| --- | --- |
| 未記入の書式と配置 | このブラウザのIndexedDBに保存。ホームの「テンプレートをバックアップ」でJSONに書き出し、「バックアップから復元・追加」で別端末にも取り込めます。 |
| 編集中の未完成書式 | 「編集中の書式をバックアップ」でJSONへ退避。同じ書式バックアップの取込みから編集を再開します。 |
| 途中の契約 | 契約画面からパスワード付きの暗号化JSONを明示的に保存。ホームの「途中保存ファイルから再開」で読み込みます。旧`.keiyaku`形式も読み込めます。 |
| 完成した契約 | 署名済みPDF・監査記録JSON・交付記録JSONをファイルとして保存し、事業所の保管規程に沿って管理します。 |

署名中の個人情報をブラウザに自動保存しません。ホームへ戻っただけなら同じタブから再開できますが、再読み込み・タブ終了後の再開には途中保存ファイルが必要です。直前の完成書類もメモリ内だけに保持され、再読み込み・タブ終了・次の署名開始で失われます。

テンプレートにもPDF全体が保存されます。**未記入の原本を使用してください。** 個人情報入りPDFを取り込むと、その情報もブラウザ内や書式バックアップに残ります。ブラウザのデータ削除で書式は消えるため、バックアップを別途保管してください。旧localStorageの書式は、移行先への保存完了を確認してからIndexedDBへ移行します。同じIDのバックアップを取り込んでも既存の書式・署名実績を上書きしません。

### ファイルの上限

| 操作 | 上限 |
| --- | --- |
| テンプレートのPDF | 1書式20MB。ページ数の固定制限はありません。 |
| 書式バックアップの取込み | 1ファイル64MB。大量の書式は選択して分けてバックアップできます。 |
| 完成ファイルの照合 | PDF 50MB、監査記録JSON 20MB、旧版の音声100MB。 |

保存できる総量は端末・ブラウザの容量によります。PDF選択後にページ数・容量・保存領域の目安を表示します。回転情報や原点がずれた切り抜き情報を持つPDFは、配置ずれを防ぐため読み込みを止めます。

## 記録の役割

**署名済みPDF**が人の読む完成書面です。末尾に署名者・記入者の立場・記録時刻・検証IDなどの証跡ページを追加します。

**監査記録JSON**はPDFと照合するための補助記録です。契約・書式のID、氏名、代筆・代理署名の申告、確認事項、操作履歴、端末時計による日時、PDFのSHA-256ハッシュなどを記録します。第三者発行の証明書ではなく、JSONにも個人情報が含まれます。

**交付記録JSON**は控えの交付に関する事業者の記録です。ホームの「保存ファイルを照合」から内容を読めます。PDFを併せて選べばハッシュによる対応も確認できます。相手の受領を認証する機能ではありません。

照合処理はブラウザ内で行います。一致はファイルと記録されたハッシュの一致を意味し、記載内容の正しさ・本人性・契約の有効性を判定するものではありません。

## 動作環境

Chrome・Edge・Safariなどの最新ブラウザを使用してください。タブレットを推奨します。iPadはSafariから公開URLを開いてください。ファイルアプリでローカルHTMLを直接開く方法は利用に制約があります。

最初のページ読み込みには通信が必要です。読み込み後の対面署名処理は外部通信を必要としませんが、オフラインでの再読み込みや再起動は保証しません。訪問先では契約開始前にページが開くことを確認してください。

Apple Pencilの線切れ改善と、複数ページPDFの書式保存は利用者によるiPad実機確認済みです。開発側ではChromiumによる操作・PDF出力・保存・復元などの自動検証を行っています。全端末・全PDFでの動作を保証するものではありません。

## 重要な注意事項

- **契約の有効性と電子署名法3条の推定効は別です。** 本アプリは手書き署名画像と説明・署名の記録を残すツールであり、同条の要件を満たすことを確認・保証したものではありません。SaaS形式かどうかで法的効力が決まるものでもありません。
- **ハッシュ照合の限界：** 元の監査記録が信頼できる場合、PDFの変更を検出できます。しかしPDFと監査記録の両方を変更してハッシュを再計算する改変は、この仕組みだけでは判別できません。本人性や第三者による時刻証明を保証する機能ではありません。
- **タイムスタンプは端末のシステム時計に基づくものです。** 総務省認定の時刻認証局（TSA）等、第三者機関による認定タイムスタンプではありません。
- **通信情報（IPアドレス等）は記録していません。** オフラインでも動作させるための設計判断です。
- 介護保険サービスの重要事項説明・同意を電磁的方法で行う場合、運営基準上の手続き（利用者側からの申出・承諾の取得等）は事業所側の責任で満たしてください。

根拠資料（2026年9月22日確認）：[内閣府・法務省・経済産業省「押印についてのQ&A」](https://www.meti.go.jp/covid-19/ouin_qa.html)、[電子署名法第3条関係Q&A](https://www.digital.go.jp/assets/contents/node/basic_page/field_ref_resources/517ca59b-6ea4-4179-a338-8d1b51a4d40b/4ae659c2/20240109_digitalsign_qa_01.pdf)、[指定居宅介護支援の運営基準・第4条、第31条](https://www.mhlw.go.jp/web/t_doc?dataId=82999405)。重要事項の電子交付では、方法・ファイル形式を事前に示した承諾、相手方が受け取って印刷できる提供方法なども必要です。事業所の端末に保存しただけで、利用者への交付まで完了するわけではありません。

無料の配布ツールです。法人としてのサポート保証やSLAは提供していません。遠隔・非同期署名、第三者による本人認証・時刻証明は提供していません。

## 不具合を報告するとき

GitHubのIssuesへ、端末・OS・ブラウザ、操作手順、エラー文を記載してください。実際の利用者のPDF・監査記録・署名画像は添付せず、架空の情報を使った書類で再現してください。

## 開発・検証

HTML・CSS・JavaScriptで構成し、実行にバックエンドは不要です。`index.html`と同梱のJavaScript・`lib/`を使用します。

単一HTMLの配布版を更新するには、Python 3で以下を実行します。

```sh
python3 build_standalone.py
```

`keiyaku_standalone.html`と事務所用HTMLを生成します。Mac・PCではローカルで開けます。iPadには公開URLを使用してください。

自動検証にはNode.jsとPlaywright（Chromium）が必要です。

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p build_test.py
```

Chromiumの場所を指定する場合は`PLAYWRIGHT_CHROMIUM_EXECUTABLE`を設定します。

### GitHub Pagesの更新手順

本番は`main`ブランチのルートをGitHub Pagesで公開します。`index.html`、参照するJavaScript・CSS・`lib/`が本番の実行ファイルです。単一HTMLは別の配布用ファイルなので、本番更新時には両方を揃えます。

1. 変更内容を検証し、`python3 build_standalone.py`で配布版を再生成します。
2. 対象のソース・追加モジュール・テスト・README・配布HTMLを指定してコミットします。個人情報のある書類、APIキー、キャッシュ、内部メモは含めません。
3. `main`へPushした後、Pagesのビルド完了と、本番URLで新しい画面・機能が読み込めることを確認します。

`preview/`の検証版は本番と保存キーを分けています。検証版で作った書式を本番へ移す場合は、検証版でバックアップして本番で取り込んでください。同じGitHub Pagesドメイン上の保存領域のため、サイト全体のデータ削除は検証版と本番の両方に影響します。
